Astera · project pipeline

Energy-aware CXL-MoE scheduler, stage by stage

Four stages, each one feeding real output into the next: a real model's expert traffic, timed and costed by a real memory simulator, replayed through a scheduler, and compared on a dashboard. No stage invents a number the stage before it didn't produce.

STAGE 1
Profiler
/profiler

Hooks a real Hugging Face MoE model while it runs and logs, per token, which expert each layer routes to. Splits experts into hot (frequently used) and cold (rarely used) per site.

transformers PyTorch hooks
in Mixtral-8x7B / OLMoE / GPT-2
outtrace.parquet, hot_cold.csv
STAGE 2
Memsim
/memsim

Simulates GPU HBM and CXL-attached host memory as physical devices, to get real latency, bandwidth and energy-per-bit numbers for each tier. No CXL hardware exists here, so this stage stands in for it.

gem5 DRAMSim3
in DRAM/CXL device configs
outtier_model.json
STAGE 3
Scheduler
/scheduler

Replays the real traffic trace against the real tier costs, deciding which experts sit in fast HBM versus slower CXL. Runs a naive baseline alongside the energy-aware eviction policy for a fair comparison.

cache simulation pJ/bit cost model
in trace.parquet + tier_model.json
outSimulationResult (hits, misses, energy)
STAGE 4
Experiments & dashboard
/experiments · /dashboard

Runs all three configs, HBM-only, naive, and energy-aware, over one trace and packages throughput, latency and energy into a comparison, shown live on a Streamlit dashboard.

run harness Streamlit
in SimulationResult × 3 configs
outcomparison.json → dashboard charts
Result

One table, three ways to place expert weights: HBM-only (idealised), HBM+CXL naive, and HBM+CXL energy-aware, each with real throughput, latency and total energy, driven end to end from one real model run.

Each arrow is a real file on disk, not a conceptual handoff: stage 1's hot_cold.csv feeds stage 3 directly, stage 2's tier_model.json feeds stage 3's cost model, and stage 3's results feed stage 4's comparison and dashboard. See CLAUDE.md and docs.md for the full spec this pipeline follows.
